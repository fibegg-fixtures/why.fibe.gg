# Build та тести в CI

Повне production-shape середовище, що піднімається всередині CI-джоби — з реальним test-data dump-ом — щоб прогнати на ньому E2E-сюїт. Зникає до того, як джоба завершиться.

Якщо ти колись пробував прогнати справжні end-to-end тести на спільному "staging" чи "beta" — ти знаєш цей сценарій. У базі сидять чужі тестові дані. Якийсь сервіс саме в процесі деплою. Черга забита вчорашнім ран-ом. Твій тест падає з причин, які не мають жодного стосунку до твого коду. Тоді ти борешся за слот, перезапускаєш, молишся. Потім хтось питає: "а ти базу засіяв?"

Fibe робить середовище частиною самого тестового рану. Всередині однієї CI-джоби Fibe піднімає весь стек — кожен сервіс, кожну чергу, повну базу, засіяну з твого реального test-data dump-у — прогонить твій E2E-сюїт і гасить середовище, коли джоба завершується. Жодної черги. Жодного забруднення. Жодного "воно ж працювало на staging минулого тижня".

## Що ти отримуєш

- **Повний production-shape стек, на кожну CI-джобу** — ті самі сервіси, та сама обв'язка, але тимчасові
- **Справжня тестова база** — засіяна з твого dump-у, sanitized prod-snapshot, або фікстури під конкретний suite. Не "свіжий порожній Postgres".
- **Піднімається за секунди** — Fibe тримає образи теплими, щоб джоба не платила за cold-boot
- **Ізоляція за гілкою і білдом** — кожен CI-ран отримує власну копію. Два PR-и, що чіпають той самий сервіс, не б'ються за одну чергу.
- **Нуль залишку** — джоба завершилась, середовища нема. Жодних EBS-вольюмів, які гудуть у твоєму рахунку. Жодного треду в Slack у понеділок "хтось чистив env-237?".

## Це для тебе, якщо

- Ти займаєшся release engineering, SRE або QA automation, і "білд пройшов на staging?" — щоденна лотерея
- У твоєї команди є справжній E2E-сюїт, якому потрібне справжнє середовище — реальні черги, реальна база, реальний auth-сервіс
- Флакі-фейли на статичному staging-у з'їдають години дебагу того, що не було проблемою коду
- Ти хочеш гейтити кожен merge на проходженні E2E, але не можеш загнати 30 PR-ів через одне спільне середовище

## Як це вписується

Один рядок у твоєму `.github/workflows/*.yml` (чи GitLab CI, CircleCI, Buildkite, що завгодно):

```yaml
- run: fibe up
- run: npm run test:e2e
- run: fibe down  # також спрацює автоматично при timeout-і чи cancel-і
```

Fibe-середовище для CI — це сервіс на кшталт Postgres або Redis, тільки це *увесь стек*, а не один сервіс. Та сама робота з секретами, той самий image registry, ті самі мережеві примітиви, які твій CI уже розуміє.

> Якщо зелений чек на твоєму PR доводить лише те, що код компілюється — це не CI. Це build-сервер.
